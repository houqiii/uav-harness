# VLM online mission implementation plan

**Goal:** Replace scripted browser outcomes with a server-owned observe–decide–execute–observe loop, driven by one Qwen VLM.

**Architecture:** Typed observations carry image, capture pose, telemetry, capabilities and provenance. The VLM proposes one bounded tool call plus concise observable evidence; a grounding layer computes metric target motion and enforces task limits. Vehicle/camera ports separate geometric simulation from Harness/PX4 and configured HTTP cameras. No target ground truth enters the VLM prompt. Missing observations, geometry or capability produce an explicit result, never fabricated progress.

**Tech stack:** Python/FastAPI/Pydantic/httpx/Pillow, existing MAVLink Harness, native HTML modules.

## Tasks and validation

- [x] Contracts and geometry: add brain/contracts.py and geometry.py; tests for strict tool schemas, image coordinates, ground projection, unknown ground, standoff and height limits.
- [x] Observation ports: simulation renderer moves an actual geometric camera around an independently seeded world; HTTP snapshot source binds fresh telemetry to capture and rejects stale/misaligned state. Tests compare rendered frames after movement and verify ground truth exclusion.
- [x] VLM provider: official DashScope endpoints only, bounded streaming response/deadline/cancellation; prompt includes task, constraints, fresh image, fleet state, tool results and bounded memory. MockTransport tests verify multimodal input, invalid/truncated output and no DeepSeek fallback.
- [x] Mission runner: one server-side owner per vehicle, sequential short actions, fresh frame after every motion, target confirmation/reassociation, rejection feedback, bounded rounds, pause/cancel with native hold and cancellation of pending inference. Tests prove different observations produce different actions, no stale dispatch and no overlapping operators.
- [x] Hardware execution: reuse journaled Harness actions and add position-held yaw with telemetry completion. Camera/gimbal capabilities require configured, observed devices. Tests verify PX4 wire messages and ownership rather than claiming flight validation.
- [x] API/UI: replace /v1/demo and browser timers with /v1/brain mission lifecycle, server snapshots, frame display and event/decision inspection. Main path contains no standalone DeepSeek parse button. Remove scripted outcomes and obsolete tests.
- [ ] External visual acceptance: full regression suite, wheel assets, real Qwen image/telemetry calls, browser start/pause/cancel, no-hardware mode, original workbench compatibility and updated documentation.

## Scope and operator-visible limits

This iteration runs one sequential action per agent/vehicle with a fleet-indexed observation and adapter boundary, providing a basis for swarm coordination. It does not claim multi-aircraft conflict avoidance. Hardware motion is disabled unless explicitly enabled in configuration; no API request may raise controller limits. Unknown geometry blocks target-relative motion and descent requiring terrain clearance. HTTP snapshots are configured by the operator, not model-selected URLs. Synthetic views are labeled geometric simulation; uploaded/live views retain their actual source. Real firmware/SITL and physical camera calibration remain explicit integration checks.

## Verification result

94 regression tests passed. Browser: genuine Arrearage error, no scripted progress or commands, no JS errors, legacy workbench accessible; 1536/390 px layouts have no horizontal overflow. A clean source wheel includes all new modules and excludes obsolete scripts. Independent review findings on camera pose, native cleanup, manual takeover and ownership recovery were corrected and covered by protocol-level tests.

External visual acceptance remains blocked: the configured DashScope account returns HTTP 400 Arrearage. No successful real VLM decision or physical flight is claimed. The application never substitutes canned detections or another provider. Camera selection/calibration, real firmware SITL, and flight validation remain integration work.
