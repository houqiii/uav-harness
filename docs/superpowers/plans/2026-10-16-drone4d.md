# Drone4D implementation plan

Goal: Native Drone4D online sandbox behind the existing VLM mission loop, separate from hardware.

1. Baseline/clone: inspect v0.2.0 SDK, REST contracts and native camera; baseline pytest; create feature branch. Preserve unrelated outer-workspace changes.
2. Capture contract: add drone4d/capture.py and tests/test_drone4d.py. Tests first: timeout without renderer, unique pending capture identity, reject stale/wrong vehicle replies, decode image dimensions and calibrated pose. No canned imagery.
3. SDK boundary: drone4d/client.py loads pinned official single-file SDK. drone4d/scene.py creates a fresh scene through configuration restore, no running canned mission. drone4d/port.py converts ENU/NED and camera/aircraft headings, waits observed completion, holds on cancellation, keeps native safety admission.
4. Session/mission API: drone4d/service.py shares Mission and lifecycle with BrainService; separate namespace/ownership and frame cache. drone4d/routes.py contains connect/disconnect/metadata/preview/mission/image/renderer routes. Native API/WebSocket proxy scoped to this owned session; credentials excluded from snapshots/logs/model context. Hardware switches stay unchanged.
5. Native renderer: integrations/drone4d/harnessBridge.ts joins only the backend-owned session, selects FPV sensor, exports framebuffer in render phase with actual projection and simulation time. Add visually distinct person meshes in WorldRoot, synchronized to native target world state, no names/boxes baked into frames. scripts/prepare-drone4d.py installs patch idempotently and builds upstream frontend locally. SDK/source revision recorded; no fork publication.
6. Dashboard: switch #sandbox/#hardware while retaining #console. Reuse mission panels with an explicit API prefix and independent restored mission IDs. Add native sandbox world and session controls; show missing-renderer/model/API failure honestly.
7. Verify: targeted unit/API/capture/coordinate tests, real remote isolated session integration, browser connect/capture/start/stop/page switching, no JS errors, full regression, clean wheel/assets and documentation including upstream research feature suggestions. Close temporary sessions; keep the reviewable dashboard available. Commit and push after checks.

Commands: `.venv/bin/python -m pytest tests/test_drone4d.py -q`; `.venv/bin/python -m pytest -q`; `npm run build -w apps/web` in cloned upstream; `bash scripts/mac-dashboard.sh --sandbox --http-port 8768`.
