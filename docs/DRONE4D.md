# Drone4D 在线沙盒与实机共用的意图控制闭环

当前适配 Drone4D **0.2.0 / contracts 1.2.0 / SDK 1.1.0**。源码在项目旁的 `ANet-Drone4D`，本机接入版本 `b4d83e3`。在线服务默认 `https://drone4d.agentnetwork.org.cn`，可用 `DRONE4D_URL` 改为同事提供的独立部署地址。服务端的 Linux x86-64 仿真留在远端；Mac 运行 Harness、SDK 和原生 WebGL 视图。实际验证范围及待完成项见 [验证记录](DRONE4D-VALIDATION.md)。

## 启动

在本仓库根目录运行，首次需要 Python 3.11+、Node **22.12+（22 系列）**、Git：

```bash
export DASHSCOPE_API_KEY='你的百炼 API key'
# 已配置密钥可跳过上一行；不使用 USTC API。
bash scripts/mac-sandbox.sh --http-port 8768
```

普通入口 `bash scripts/mac-dashboard.sh` 也默认准备并启用沙盒，使用 `http://127.0.0.1:8080/#sandbox`。启动后点击“创建独立沙盒”，等待原生渲染器在线，再输入任务并点击“启动闭环”。`--no-sandbox` 才会关闭在线沙盒；不需要串口。

脚本会准备 Python 依赖、缺失时拉取已验收的 Drone4D 0.2.0 源码 revision `b4d83e3`，安装并构建带 Harness 图像桥的原生前端。后续启动会复用匹配的构建。VLM 观测视图固定以 1280×720 渲染，页面只缩放显示，避免窗口尺寸影响小目标像素数量。打开 `http://127.0.0.1:8768/#sandbox`，点击“创建独立沙盒”，等待原生世界与云台在线，输入任务并启动闭环。保持页面打开，当前版本的 RGB 从浏览器的原生 FPV 帧缓冲读取。

已有源码：`export DRONE4D_SOURCE=/你的路径/ANet-Drone4D`。仅重建视图：`.venv/bin/python scripts/prepare-drone4d.py`。配置项在 `drone4d`，含服务地址、源码/构建目录、速度、采集/动作时限、初始云台俯角和光学倍率。沙盒准入按远端 Retry-After 等待，可点击“结束沙盒”取消等待；初始化失败后重试会保留已创建的会话，不重复消耗创建额度。SDK、REST 与 WS 均直接访问所配服务，不继承环境代理；这保证公开接入的 PoW 挑战和应答使用同一出口地址。

## 任务如何运行

初始场景只有一架地面飞机、一名静止红帽人物和原生城市环境，没有预运行的任务。初始化云台向下 15°、光学倍率 1；默认任务约束为起飞 50 m、扫描步长 30°、最大单步 30 m、最小水平间隔 30 m、最终三维距离不超过 50 m、最大任务半径 450 m。场景种子从候选道路位置选择人物位置，初始距离约 150 m；页面可以重置远距场景，复用当前会话。默认人物放在候选道路位置，150 m 新位置仍需在线确认无遮挡；树冠遮挡场景下，缺少脚点会阻止接近。目标位置用于场景构造、渲染和独立评测，不提供给规划器。

1. 原生渲染器返回当前飞机的 RGB、相机内参、世界姿态、仿真时间；后端核对请求 ID、飞机 ID、图像尺寸、图像/遥测时间和位置。
2. **同一个 Qwen VLM** 接收自然语言、图像、遥测、约束、目标记忆及上次实际结果，每次提出一个动作。没有额外语义 LLM，也没有固定识别结果。
3. 无目标时，模型可选择转向、调整云台或 `search_move` 探索位移；探索方位、步长由模型决定，观测中包含已访问位置。候选过小时，模型可先调转取景，再调用原生 EO 光学变焦（1–5 倍；仅对已识别的 GX40 标定规格开放）。看到目标后，程序要求两次一致的新观测，才允许接近。
4. 目标框的可见足点通过标定相机与地面模型计算方位、距离和误差；模型不能直接编造米数。接近距离受单步上限、保守观察间距、活动范围和高度限制约束。
5. 云台适配器续期最后一次已接受的指向（上游 operator 指向 60 秒仿真时间后到期），不会用固定角度覆盖模型的新选择。位移由 Drone4D `safe_transit` 处理路径准入；原地转向用位置保持 `direct goto + yaw_rad`（0.2.0 的路径提供者不消费 yaw）。每次收到指令确认后，继续等待实际位置/速度/航向/云台角度达标；单次确认不等于动作完成。
6. 执行后重新采图和规划。目标丢失、姿态变化、图像超时或几何不可靠时不沿用旧接近指令。VLM 自行决定接近、改变高度和悬停；只有当前视觉几何的三维距离加误差不超过 50 m，才能报告接近完成。变焦不改变物理距离；这不是全局最优摄影点的保证。

规划上下文只保留实际工具动作与结果，不重复喂入旧图像框及旧画面描述，避免旧坐标锚定。历史目标几何可以生成当前云台朝向提示，但须用当前图像重新确认。放大检查失败后须恢复搜索俯角和倍率；只有水平视场足够覆盖扫描步长、俯角在有效地面搜索范围内的观测才计入扫描覆盖。

“仅寻找”与“接近观察”保留不同目标语义。普通找人任务不会自动扩展成接近或下降。中止时排空可能仍在发送的 SDK 调用，再确认停止；多次取消也不能跳过这一步。起飞预旋转阶段尚未离地，不会被误判为已停止的地面状态。

## 沙盒与实机页面

- `#sandbox` 使用 `/v1/sandbox/brain`、独立沙盒会话、原生 RGB 与仿真遥测。
- `#hardware` 使用 `/v1/brain`、现有 MAVLink 与 HTTP 相机适配器。未配实机时显示“实机接口待连接”，不会使用几何假相机代替实机。
- `#console` 保留已有原子指令工作台。旧的 `--offline` 几何环境仍可独立用于单元调试。

切页不会切换任务的执行器，也不会自动取消后台任务；任务 ID、观测和图像缓存按页面隔离。沙盒原生渲染器在切页后保留。完整控制连接断开时，上游安全系统会接管，实测曾触发安全落地；重新接入不会强制解除 SAFETY_ACTIVE，须等安全动作完成。结束任务会保持位置；“结束沙盒”则关闭整个远端会话。实机部署仍需配置真实飞控、相机标定、姿态和地面/测距来源，再使用 `--sandbox --config 你的配置.json` 同时提供两套页面。

远端 token 只保存在被 git 忽略的 `state/.../drone4d-session.json`（0600）及原生客户端存储；不进入模型输入。启用 `HARNESS_API_TOKEN` 时，管理、图像提交和任务接口都需此 token；原生代理另行验证所属会话的 sandbox token，禁止跨会话访问。非本机监听仍要求管理 token。

SDK 和原生页面共用后端维护的当前令牌；续期更新后立即落盘，REST 请求与续期串行，WS 重连使用最新令牌。页面仍持有之前已授权的令牌时，可通过所属会话代理继续连接。有效凭据重启后直接恢复会话；若凭据丢失但服务仍保留活动会话，按上游语义最多尝试一次 `force_new`，占用公开入口第二个名额，仍受配额限制，不会无限创建。

## 当前边界

当前在线控制使用上游 FleetSim 的 mock 物理后端，动作完成由仿真遥测核验；PX4 SITL/HIL 仍需后续单独验证。RGB 使用原生城市点云/几何和附加的人物帽子网格：有真实相机投影、遮挡和飞行变化，但不是照片级合成数据。50 m 高度下红帽可能只有几个像素，识别失败应通过视角、倍率或环境设计解决，不能用场景真值冒充识别。当前只提供单机默认场景；多机任务分配、覆盖最优化、障碍物理解、目标跟踪身份一致性和摄影点全局优化尚未实现。半径 450 m 是活动边界，不代表单圈相机扫描已覆盖全部地面。

上游升级后先检查 SDK / contracts / camera projection / ENU-NED / 指令终态，再更新适配器。不要直接把包版本相同当成行为相同；构建目录的 `harness-integration.json` 记录实际源码 revision 和图像桥哈希。原生视图较大的 bundle 警告来自上游构建，当前仍需首次下载/编译。

## 后续使用自有 Linux 服务

源码可以拉到 Mac；目前受平台限制的是仿真后端。上游要求 Linux x86-64，StateRing 的 seqlock 依赖 TSO，暂不支持 aarch64。可按上游 README 在 Linux 部署，保持现有 dashboard 在 Mac 上，通过 HTTPS 地址或 SSH 转发到本机回环端口连接。此时只需设置 `DRONE4D_URL` 后重启 Harness；同一 VLM、任务循环和界面继续使用。换地址前结束旧会话，或保留其凭据以便稍后回到原服务。

参考：[上游启动说明](https://github.com/ANetResearch/ANet-Drone4D#Get-started)、[平台与部署说明](https://github.com/ANetResearch/ANet-Drone4D/blob/main/docs/19-%E9%83%A8%E7%BD%B2%E4%B8%8E%E8%BF%90%E7%BB%B4%E8%AF%B4%E6%98%8E%E4%B9%A6.md)。

## 约 150 米场景与双视角评测

默认任务为“帮我找一个戴着红帽子的人，自主规划搜索、移动和高度，直到与他三维距离50米以内，然后悬停监控”。操作员面板单独显示初始真值距离、当前真值三维距离、累计实际航程和验收结果。这些数据不进入 VLM 观测或规划记忆。验收需要初始距离在 140–165 m、任务完成、当前真值距离不超过 50 m，且飞机在空中速度低于 0.3 m/s。

相同种子可复现场景，不保证复现模型动作。换种子后仍由模型从图像搜索，没有注入目标方位或固定航线。单轮非法模型输出或网络超时最多重新采集并重试两次，持续失败则保持并报告错误。

沙盒首页以三栏同屏展示原生云台 FPV、原生第三人称跟随和 VLM 决策依据。第三人称页面不会领取图像请求、写入采集状态或向飞控发控制命令；规划仍只使用 FPV。决策面板保存每轮帧编号、观测摘要、计划和动作；它展示模型输出的决策说明，不是模型内部隐藏思维链。较窄屏幕自动换行，历史帧与详细事件保留在下方。

搜索可被当前图像线索立即打断：疑似候选优先居中、放大和复核；确认后即可接近，无须先扫满一周。完整扫描覆盖只限制“未找到”的结论，不限制接近或成功。约 150 m 场景的候选位置全部避开初始正东视野；搜索方向仍由 VLM 决定，目标方位不提供给模型。
